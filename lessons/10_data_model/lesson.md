# 第 10 章：数据模型

### 特殊方法是 Python 语法背后的协议

表达式不会绕过对象模型。常见操作会委托给特殊方法：

```text
a == b       → a.__eq__(b)
a + b        → a.__add__(b)，必要时再尝试 b.__radd__(a)
len(value)   → value.__len__()
value[key]   → value.__getitem__(key)
key in value → value.__contains__(key)，或退回迭代协议
```

`NotImplemented` 是特殊返回值，表示“当前这个实现不认识另一侧的类型，请 Python
继续尝试其他协议分支”。它不是 `NotImplementedError`，也不是由业务代码主动抛出的
异常。例如 `1 + money` 会先尝试 `int.__add__(1, money)`；如果得到
`NotImplemented`，Python 才尝试 `money.__radd__(1)`。

### 相等、哈希与不可变值对象

相等和哈希必须满足：

```text
a == b  ⇒  hash(a) == hash(b)
```

因此金额和币种都相同的两个 `Money` 可以在 `set` 中去重，也可以互换地查询同一个
字典键。用 `@dataclass(frozen=True, slots=True)` 表达值对象，可以同时获得按字段比较、
稳定哈希和禁止普通属性重新赋值的语义。

“能够通过特殊手段修改”不等于“适合修改”。如果一个对象已经作为 `set` 元素或字典键，
再用底层方式改变参与哈希的字段，容器仍按旧哈希位置保存它。此时对象虽然看起来还在
容器里，查找却可能失败；这正是可变对象通常不应参与哈希的原因。

### 相等比较不会产生数组式结果

内置 `list` 的 `==` 会从左到右比较对应元素，并返回一个 `bool`：元素都相等且长度相同
才是 `True`。某些第三方数组类型可能把 `==` 定义为逐元素结果；这属于该类型自己的
数据模型，不是所有“数组状对象”的统一行为。需要判断一个比较结果时，应先知道操作数
的具体类型和它实现的协议。

### 值对象的表示与业务错误

`repr(value)` 面向开发和调试，理想情况下应清楚、无歧义；`str(value)` 面向用户；
`format(value, spec)` 让格式化字符串把格式规则交给对象。不同币种相加不是“另一种类型
可能会处理”的问题，而是已经识别出两个 `Money` 后发现业务规则不允许，因此应抛出
明确的 `CurrencyMismatch`，而不是返回 `NotImplemented`。

### 第 10 章速记

```text
运算符调用特殊方法；不支持的类型组合返回 NotImplemented。
相等对象必须同哈希；参与哈希的状态必须稳定。
frozen 表达不可变意图，slots 限制常规实例存储，但都不是安全边界。
内置 list 的 == 返回一个整体 bool；第三方类型可以定义不同协议。
```
